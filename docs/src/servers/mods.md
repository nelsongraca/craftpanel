# Mods & Plugins

Mod management is available for server types that support it: Fabric, Forge, NeoForge, Quilt, Paper, Spigot. Plugin management for proxy types follows the same flow where supported.

Requires `server.mods` permission.

## Adding Mods

1. Open the **Mods** tab on a server's detail page
2. Search [Modrinth](https://modrinth.com) directly from the panel — results are automatically filtered by the server's loader and Minecraft version
3. Select a mod to add it to the server's mod list
4. Choose a version pin strategy (see below)
5. The change is saved immediately; it takes effect on the next restart

## Version Pinning

Each mod entry has two options:

| Strategy   | Behaviour                                                                                                                          |
|------------|------------------------------------------------------------------------------------------------------------------------------------|
| **Pinned** | A specific version is locked. itzg downloads exactly that version on restart. Nothing changes until the pin is explicitly updated. |
| **Latest** | itzg downloads the latest compatible version on every restart. Updates happen automatically but may introduce breaking changes.    |

!!! tip
Pinned is the recommended default for production servers. Use Latest only if you want automatic updates and are prepared to handle occasional compatibility issues.

## Updating Mods

The mod list UI shows the installed version and the latest available version for each mod. A one-click **Update** action updates the pin to the latest version and marks the server for a restart.

## Disabling Mods

Each mod row has a toggle. Disabling a mod keeps it in the list but excludes it from the container's `MODRINTH_PROJECTS` list; itzg removes the corresponding file from `mods/` on the next start. Re-enabling adds it back. Use this to A/B test a mod without losing its pin configuration.

Like every other mod change, the toggle only takes effect on the next server restart.

## How It Works

The mod list is persisted in the master database and passed to the itzg container via the `MODRINTH_PROJECTS` environment variable. itzg handles the actual download and placement into the `mods/`
directory on container startup. Disabled mods are omitted from that variable.

Mod config files (generated by mods on first run) are accessible via the [File Explorer](./files-console.md).

## Client Pack Export

For Fabric, Forge, NeoForge and Quilt servers, you can export a client modpack (`.mrpack`) that Prism Launcher (and forks) can import as a new instance. The pack contains only the mods **required on the client** — server-only mods (e.g. chunky), singleplayer-only mods, and client-optional enhancements are left out.

### Using the export

1. Open the **Mods** tab on the server's detail page (requires `server.view`).
2. Click **Client Pack** in the header (visible only when at least one mod is installed).
3. Review the preview: the included mods, skipped mods, Minecraft version and resolved loader version.
4. Click **Download .mrpack**.

### What goes into the pack

- Each included mod's Modrinth CDN download URL plus its SHA-1/SHA-512 hashes, so Prism can validate downloads.
- The Minecraft version and loader version matching the server (Fabric loader, Quilt loader, Forge or NeoForge).
- Dependencies are limited to `minecraft` and the loader — no transitive dependency resolution.

### What's left out

- **Manual uploads:** only Modrinth-tracked mods are exported; jars you uploaded yourself are never included.
- **Configs / overrides:** no server config files are bundled — too sensitive to ship to clients.
- **Non-client mods:** server-only, singleplayer-only, client-or-server redundant, and client-optional mods are excluded.

### How the loader version is chosen

The resolved loader version mirrors itzg's behaviour:

1. If the server sets a loader env var (`FABRIC_LOADER_VERSION`, `QUILT_LOADER_VERSION`, `FORGE_VERSION`, `NEOFORGE_VERSION`), that exact value is used.
2. Otherwise the panel queries the loader's official metadata API and picks the newest compatible release for the server's Minecraft version.

The `.craftpanel.json` export (server configuration) is unaffected by this feature and stays available separately.
